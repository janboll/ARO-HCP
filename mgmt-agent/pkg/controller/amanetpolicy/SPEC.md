# AMA NetworkPolicy Controller for HCP Namespaces

## Context

AMA (Azure Monitor Agent) runs in `kube-system` and needs to scrape Prometheus metrics from HCP pods in `ocm-*` namespaces. HyperShift's control-plane-operator creates NetworkPolicies in these namespaces that only allow ingress from namespaces labeled `network.openshift.io/policy-group: monitoring`. The OSS Prometheus namespace carries this label, but `kube-system` does not. As a result, AMA scrapes time out for all HCP targets except kube-apiserver (which has its own permissive `kas` NetworkPolicy on port 6443).

A new controller in mgmt-agent will watch HostedControlPlane CRs and create a targeted NetworkPolicy in each HCP namespace allowing AMA metrics pods to reach HCP endpoints.

## Controller: `AMANetworkPolicy`

**Package**: `mgmt-agent/pkg/controller/amanetpolicy/`

**Trigger**: HostedControlPlane CR events (reuses existing `hsInformers` HCP informer). Secondary watch on its own NetworkPolicies (labeled `app.kubernetes.io/managed-by: mgmt-agent-ama-netpolicy`) for convergence on external edits/deletes.

**Gate**: Only created when `--monitoring-api-group=azmonitoring.coreos.com` (same gate pattern as monitor translator).

### Sync Logic

1. Receive HCP key `<namespace>/<name>` from workqueue
2. Look up HCP via lister; if not found or has `DeletionTimestamp`, return nil (OwnerReference handles cleanup)
3. Build desired NetworkPolicy
4. Apply via Server-Side Apply (typed client, `k8s.io/client-go/applyconfigurations/networking/v1`)

### NetworkPolicy Spec

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: ama-metrics-allow
  namespace: <hcp-namespace>
  labels:
    app.kubernetes.io/managed-by: mgmt-agent-ama-netpolicy
  ownerReferences:
  - apiVersion: hypershift.openshift.io/v1beta1
    kind: HostedControlPlane
    name: <hcp-name>
    uid: <hcp-uid>
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: kube-system
      podSelector:
        matchLabels:
          rsName: ama-metrics
```

Key design choices:
- **`podSelector: {}`** matches all pods in the namespace (mirrors existing `openshift-monitoring` policy)
- **`kubernetes.io/metadata.name`** is immutable and auto-set by Kubernetes -- canonical way to target a specific namespace
- **`rsName: ama-metrics`** is the stable label on AMA scraper pods -- scopes access to only AMA, not all of kube-system
- **OwnerReference** to the HCP ensures automatic garbage collection on HCP deletion

## Key Patterns to Reuse

- `ksmhcp/controller.go` (`mgmt-agent/pkg/controller/ksmhcp/controller.go`): typed SSA apply, HCP informer usage, OwnerReference setup, `enqueueForOwner` pattern for secondary resource watch
- `monitortranslator/controller.go`: workqueue setup, namespace prefix filtering, `Run`/`processNextWorkItem` boilerplate
- `options.go` existing gate: `if o.KSMImage != ""` pattern for conditional controller creation

## Alternatives Considered and Rejected

- **Label `kube-system` with `network.openshift.io/policy-group: monitoring`**: Too broad, allows all kube-system pods, not just AMA
- **Piggyback on monitor translator**: Violates SRP, couples unrelated concerns, lacks HCP OwnerReference
- **Static Helm-deployed NetworkPolicy**: HCP namespaces are dynamic, no way to know names at deploy time
- **Watch Namespaces instead of HCPs**: Cannot set OwnerReference for cleanup, no precedent in existing controllers
